# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).

## [1.0.0] — 2026-09-27

Первая версия с интерфейсом оператора, ML-аналитикой и C++ ядром.

### Добавлено
- Генерация мнемосхемы оператора из `configs/config.yaml` и вкладка «Генератор» для любой установки.
- Веб-интерфейс на HTML/CSS/JS без сборщиков и CDN: мнемосхема, тренды с коридором нормы и прогнозом,
  алармы, ИИ-аналитика, демо-сценарии; русский, английский и китайский языки; светлая, тёмная и
  системная тема.
- C++17 ядро аналитики (pybind11): потоковый детектор выбросов, дрейфа и залипания; прогноз
  «время до аларма». Python-реализация с идентичными результатами для систем без компилятора.
- Многомерная модель PCA-MSPC с объяснением виновного тега, предалармы, группировка одновременных
  отклонений в одно событие «смена режима».
- Движок алармов по ISA-18.2 (зона возврата, задержка, квитирование, отложенные) и KPI EEMUA 191.
- REST API, WebSocket, токен оператора `SCADA_API_TOKEN`, эндпоинты `/api/health` и `/api/health/live`.
- Режим `--demo`: физическая модель насосной станции с подачей неисправностей.
- Версионные миграции PostgreSQL, пакетная запись, журнал ML-инсайтов.
- Подстановка переменных окружения в конфигурации: `${PLC_HOST:-localhost}`.
- Dockerfile и `docker-compose.yml` (эмулятор ПЛК + PostgreSQL + SCADA).
- 75 автоматических тестов, CI: линт Python и C++, сборка ядра на Linux и Windows, тесты на
  Python 3.10 и 3.12 с реальным PostgreSQL, проверка Docker-стенда.

### Исправлено
- После обрыва связи с ПЛК опрос больше никогда не возобновлялся.
- Аларм записывался в БД на каждом цикле опроса, пока значение было за порогом.
- Алармы всех устройств записывались на устройство `plc_main`.
- Двойной вызов `shutdown()` и `sys.exit()` внутри задачи asyncio при остановке.
- Эмулятор разрывал соединение вместо ответа кодом исключения Modbus.
- CI запускал тесты из корня проекта, хотя они были перенесены в `tests/`.

### Изменено
- Время в истории и алармах хранится как `TIMESTAMPTZ` (миграция 002 сохраняет моменты времени).
- Пользователь БД по умолчанию — `scada` (задаётся `DB_USER` в `.env`).
